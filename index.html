PP Friend

自托管的实时语音助手客户端。手机只做两件事：采音、放音；识别、对话、合成全部交给你自己的服务端（代码里叫 brain）。

这个项目本身的开发就是用 PP Friend 跑的：对着手机说话来驱动编码，需求、审查和修复一路靠语音说完。

主要能力

全双工

你说话它听，它说话你听，两个方向同时开着，不用轮流按键。

可打断

它正在说的时候你开口，本地断句确认连续 350 ms 人声后立刻停播，并把没听到的那段文字报给 brain，它不会以为自己讲完了。打断是独立开关，默认关闭。

后台不中断

前台服务撑住录音，切到别的 App 或锁屏，对话继续。

本地断句

Silero VAD 跑在手机上（Rust），按 512 采样（32 ms）一帧推进。只把成句的片段传上去，不是把连续音频整段推流。

声纹门控

ECAPA 声纹和这一段语音算余弦相似度，每段最多看开头 3 秒，低于阈值（默认 0.4）整段丢弃：家人的话不上传，也不进 agent 的上下文。

多档案

每个档案一套 brain 配置、一份独立历史，可以同时跑；只有聚焦的那个播声音，其余只记文字。想开一段新对话，换个 brain 名字就行。

架构与数据流

手机端不持有对话上下文，上下文在服务端。手机落盘的只是用于展示的历史，不进任何请求，删掉不影响对话。

麦克风
→
音频引擎（Kotlin）采集 / AEC / Opus 编码
→
断句与门控（Rust）Silero VAD + ECAPA
⇄
brain（你的服务端）识别 / 对话 / 合成
→
扬声器

上行 Ogg Opus 16 kHz，下行 Ogg Opus 24 kHz（解码后重采样到 16 kHz）。通信是 HTTP + MessagePack，两条独立的长轮询循环。

技术栈
UI / 业务Flutter（Dart 3.13）
本地断句Rust + Silero VAD，flutter_rust_bridge 2.13
声纹门控Rust + ECAPA（int8 ONNX，23 MB）；声纹由本站注册工具生成
音频引擎Android 原生（Kotlin）：AudioRecord / AudioTrack / AEC
上行 / 下行Ogg Opus 16 kHz 上行；Ogg Opus 24 kHz 下行，重采样到 16 kHz
与 brain 通信HTTP + MessagePack，两条独立长轮询循环
历史落盘NDJSON，按 1 MB 分片，只增不删，仅用于展示
平台Android arm64，minSdk 29

隐私与自托管

  • 识别、对话、合成全部运行在你自己的服务端，音频不去第三方服务。
  • 声纹门控在手机本地完成：不够像本人的片段在上传之前就被丢弃。
  • 声纹注册在浏览器里完成，录音和推理都不出本机（见本站声纹注册工具）。
  • 对话上下文在服务端，由 brain_id（人起的名字）区分；客户端只保存展示用历史。
  • 客户端与服务端之间用一个可选的 Bearer token 鉴权；token 为空表示该部署未启用鉴权。

快速开始

前提：Flutter 3.47 以上、Android NDK、Rust 工具链。新克隆不需要 NDK 就能构建，jniLibs 里的 .so 已入库。

tools/fetch_onnxruntime.sh   # 宿主跑 cargo test 才需要
flutter build apk --release

只有改了 Rust 源码才需要重跑 tools/build_rust_android.sh（产物要一起提交）。

没有 brain 也能端到端自测：仓库带了一个按协议手写实现的假 brain，内含一份独立的 MessagePack 实现，用来验证协议理解有没有跑偏。

tools/mock_brain.py

声纹注册工具

说话人识别需要一份本人声纹。在浏览器里录一段话或选一个音频文件，算出 192 维声纹并下载 spkemb.f32（768 字节，float32），再到 App 的设置 → 通用 → 说话人识别里导入。录音和推理都在浏览器本地完成，音频不上传。
