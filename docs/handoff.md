# 对齐结论 · 交接文档

记录本轮讨论中**已经对齐**的决定，以及**尚未决定**的部分。
供主会话接手，避免两边理解不一致。

> ⚠️ **协议细节以 [`brain-api.md`](./brain-api.md) 为准。**
> 本文档 §A 里关于载荷格式的描述**已过时** —— 协议后来从
> multipart/JSON 改成了 **MessagePack**。下面只保留了结论性内容，
> 具体格式不再重复，避免两处说法不一致。

## A. 架构：brain API 取代手机端 STT/TTS

**核心转变**：手机端只做两件事 —— 采音、放音。
识别、对话、合成全部由 brain 承担。**对话上下文**（它记得什么、聊到哪儿了）
全在服务端，手机端不持有。

> 手机端后来加了一份**展示历史**（重启之后还能往上翻，见 `brain-api.md` §7.2）。
> 那和这句话不矛盾：它是纯展示，**不进任何请求**，删掉不影响对话。

### A0. `brain_id` 是什么 —— **不是生成的，是人起的名字**

像人的名字一样有语义，标识"你在跟哪个 brain 说话"，由用户在客户端配置。

```
brain_id = "员工3"
```

推论：

- 客户端只要一个**文本输入框**，不需要 UUID 生成器，
  也不需要服务端发号接口
- 状态按名字存在服务端，**同一个 `brain_id` 跨 App 重启仍是同一段对话**
- 想开一段全新对话，换个名字就行
- 它同时出现在 `/human-to-brain` 和 `/brain-to-human` 里，两边必须一致

### A0b. 认证 —— Bearer token

`/human-to-brain` 和 `/brain-to-human` 都支持：

```http
Authorization: Bearer <token>
```

- token 是**用户配置项**（和 `brain_id` 一样），不是生成的
- **token 可能为空** —— 即该部署未启用鉴权。
  为空时客户端**不发送**该 header（而不是发空的 `Bearer `，
  那样容易被判成格式错误）
- 401 **不要**当网络问题无限重试 —— 那是配置错误，
  应当直接提示"token 无效"

### A1 / A2 / A3. 端点与载荷格式 —— **已变更为 MessagePack**

原方案是 `/human-to-brain` 走 multipart、`/brain-to-human` 按顶层
`Content-Type` 分派 JSON 或 multipart。

**服务端最终给的规范是：请求和响应都是裸 MessagePack**，
没有 multipart、没有 boundary、没有 Content-Type 分派。

```
/human-to-brain   req { brain_id: str, audio: bin }              // Ogg Opus 16k
                  ret { kind: "text", text: str }
/brain-to-human   req { brain_id: str }
                  ret { kind: "empty" }
                    | { kind: "text", text: str, audio: bin }    // Ogg Opus 24k
```

`kind` 的取值是 `empty` / `text`（不是早先写的 `response`）。

详细字段、Content-Type 取值、以及客户端实现要点见 `brain-api.md` §2–§3。

### A4. 音频格式 —— 已定

| 方向 | 格式 | 采样率 |
|---|---|---|
| 上行（`/human-to-brain`） | `audio/ogg`，Ogg Opus | **16kHz** |
| 下行（`/brain-to-human`） | `audio/ogg`，Ogg Opus | **24kHz** |

两个方向都是 Ogg Opus，但**采样率不同** —— 跟着两端的模型走：
STT 吃 16k，TTS 出 24k。
（有实测佐证：现有 MOSS-TTS 的 `pcm` 输出就是 24000Hz。）

对客户端意味着**两个方向都要做 Opus 编解码**，且下行还要重采样：

| 方向 | 客户端要做的事 |
|---|---|
| 上行 | PCM16 16k → **Opus 编码** → Ogg 封装 |
| 下行 | Ogg 解封装 → **Opus 解码** → **重采样到引擎速率（16k）** |

纯 Dart 没有可用的 Opus 编解码器，两块都得走原生：
解码用 `MediaExtractor` + `MediaCodec`，
编码用 `MediaCodec`（`audio/opus`）+ `MediaMuxer`（`MUXER_OUTPUT_OGG`）。

> ⚠️ **别假设解码出来的采样率等于声明的采样率。**
> Opus 内部固定跑 48kHz，Ogg Opus 头里的 "input sample rate" 只是提示。
> Android 的 `MediaCodec` 解码 Opus 通常**直接给 48000Hz**。
> 必须**读解码器实际输出的采样率**再重采样，写死 24k 会变速
> （音调变低、语速变慢），而且很难查。

**上行压缩选型**（3 秒语音）：WAV 96KB / µ-law 48KB / gzip 40KB / **Opus ~6KB**。
选 Opus —— 16x vs 2x 不是一个量级，且下行本来就要写 Opus 解码。

**minSdk 提到 29**（原方案是 24，已推翻）：

| 能力 | 最低 API |
|---|---|
| Opus 解码 | **21** |
| Opus 编码 | **29** |
| `MUXER_OUTPUT_OGG` | **29** |

原方案保留 24 的前提是"`/human-to-brain` 收 WAV，没编码器就回落"。
**服务端规范只收 `audio/ogg`**，这个前提不成立了 ——
与其留一个"看起来成功实际失败"的回落，不如把门槛提到 29。

即使提到 29，客户端**仍然在运行时用 `MediaCodecList` 探测**编码器，
不是只判 API 级别 —— OEM 差异真实存在。探测失败就明确报错。

### A5. 打断语义 —— 已对齐（我原先的理解是错的）

- response 的**文本永远进入消息流**，无论是否被打断
- 只有 **AI 语音**会被清空
- 因此 **服务端不需要加 `since` 字段**。客户端本地已有的 `epoch` 机制就够：
  在途的音频分块全部作废，文本该进流照样进流
- **不要自动打断（barge-in）**：收到就播，不做双讲检测

→ 可以删除：`playbackLevel` 参考电平、打断阈值、双讲余量、以及对应的 UI。
（这套是之前为了"自动打断"做的，现在不需要了。）

**A5 修订（2026-10-15）**：`docs/需求-闭麦与打断.md` 把这条推翻了半个 ——
打断不再"不做"，而是做成**用户可见的独立开关，默认关**（关着就是 A5 原文）。

- **关着**：收到就播。此时仍保留那道**双讲余量**门（AI 在出声、麦克风没明显
  高过播放电平时喂数字静音）—— 目的是防回声自激，不是做自动打断。
  它以前是隐形的，现在挂在开关的默认态上，有据可查。
- **开着**：本地断句一判到人声就停播，不设双讲门槛。代价是 AEC 不干净时
  它自己的声音可能把人声吵醒（等于自己打断自己）。
  但「判到人声」不是「刚听到有声那一瞬间」—— Silero 那个 `speaking` 标志
  要静满 `vadMinSilenceMs` 才落回，一声咳嗽也能扛出 700ms+。所以还要
  **连续说够 350ms** 才认（`bargeInMinSpeechMs`），否则咳嗽就打断。
- 被打断时要**上报"我哪一段没听到"**：`/human-to-brain` 加 `unheard_text`
  （没听到的那部分文字）+ `heard_ms`（见 `brain-api.md` §5.3b）。
  否则 brain 以为自己讲完了，下一轮接着"刚才说的那个"往下讲，
  用户只能装懂。**报文字而不是毫秒** —— 给 brain 一个时间点，它还得
  自己对一遍；要翻成文字，得它在 `/brain-to-human` 里给一份按句的
  时间账（`spans`，可选字段）。
- 另有「闭麦」开关：麦克风帧在本地换成静音，一个字节都不上传。
  闭麦期间打断天然失效（本地断句听不到东西）。

### A5b. 已确认（原待确认项）

- ✅ `/brain-to-human` 收到 `empty` 就**继续轮询**，不停不等
- ✅ **不存在协议层错误响应**，只有网络问题，客户端自己重试（退避 + 上限）
- ✅ 上行音频格式：`audio/ogg`，Ogg Opus，16kHz

### A6. 清空播放队列的触发方式 —— **已定**

**通知栏按钮 + 音量减键，两个都做。**

- 通知栏「停止说话」按钮 —— 覆盖后台/锁屏（这是设计目标场景）
- 音量减键 —— 只在 App 前台、且正在播 AI 语音时拦截，其余时候放行

只清音频，文本照样进消息流。

**A6 修订（2026-10-16）**：音量减键这一路做成**开关，默认开着**（设置页
「通用」里的「音量减键清空队列」）。理由是"AI 正在说话时想调小音量"和
"想让它闭嘴"是两个人人都会有的意图，而键被吞掉时音量调不动，用户只会
以为手机卡了 —— 这个抱怨实际出现过一次。关掉开关之后，音量减恢复成
普通调音量；"让它闭嘴"仍然有通知栏那个按钮兜着，不是没有路走。

### A7. 说话人识别（ECAPA 声纹）—— 已实现

实现链路、量化原理和实测数字见 [`speaker-verification.md`](speaker-verification.md)，
本节只留结论。

目标：**只上传本人的声音**，这样用户不用频繁闭麦，家人也不必担心
随口说的话被卷进 agent 的上下文。

- 分工：**Silero 决定"有没有人说话"，ECAPA 决定"是不是本人"**。
- 为什么不用 pVAD 判身份：pVAD 的 sigmoid 主要反映"像不像语音"。
  实测里目标人和家人说话都能到 0.9；把参考声纹换成零向量、随机向量
  或另一个人的，输出几乎不动。它能回答"这段像不像人在说话"，
  回答不了"是谁"。
- 判定：一段话先去掉两端外扩，再从 Silero 的逐帧概率里挑出判为语音的
  帧拼起来，最多取 3 秒，送进 ECAPA 算 embedding 和注册声纹的 cosine。
  低于 `pvadMinCosine`（默认 0.4）就**整段丢掉** —— 不上传、不进消息流。
  段中间的停顿是纯静音，混进去会稀释 embedding，说得越长、停顿越多，
  本人的 cosine 反而越低，所以必须跳过。
- 短段：不足 0.3 秒的语音不做比对（embedding 不稳），有 pVAD 时退回
  它的逐帧占比；当前 Dart 侧只挂 ECAPA，没有 pVAD 可比时直接放行。
  推理失败也只摘掉比对器，不影响断句和上传。`pvad.onnx` 已经不再随
  仓库分发，Rust 里的 pVAD 路径保留着，但默认没有模型可用。
- 声纹：192 维，L2 归一化，768 字节的 `spkemb.f32`。注册网页和手机
  必须用同一个 checkpoint（SpeechBrain `spkrec-ecapa-voxceleb`），
  换模型之后旧声纹就不能再比了。注册入口是 `tools/voiceprint/enroll/` 的
  纯 JS 网页（onnxruntime-web，音频不出本机；线上在项目站点的 `/enroll/`），
  设置页用文件选择器导入。
- 模型：注册页本地用 fp32、线上用 int8（22 MiB，避免 81 MiB 的下载），
  APK 用同一个 checkpoint 的 int8（23 MiB）。实测 embedding cosine min 0.986 / mean 0.992，同人判定
  分只挪 -0.006，旧声纹可以直接用。
- 存储：声纹在应用私有目录 `voiceprint/spkemb.f32`，可随时删除。
- 已知限制：
  - 判定是**前缀式**的：最多只看这一段开头的 3 秒。你先说、家人紧接着
    在同一个 VAD 段里继续说，这一整段都会按你的声纹放行。要让 VAD 把
    两段切开，中间停顿得超过 `vadMinSilenceMs`（默认 700ms）。
  - 只做整段判定，不分离重叠语音，也不在段内检测换人。

（`graphic_eq` 上下对称，不补。）

### B7. 档案（profile）

需求原文："我可能有好几个 brain，各自配 brain_id 和 URL，可切换；
一个档案一份历史；多个同时跑，但只有一个真正完整交互。"

已经实现，细节见 `brain-api.md` §7。三条用户明确提过的：

- 头像**图本身不裁**（等比缩放到放得下），但**显示时被裁在按钮那个圆里**，
  不许以方形越过按钮边界；并且半透明压上去，透出底下的主题色。
  （用户先说过"不裁剪"，看到方形溢出的实物后改口要遮罩 + 透明）

- 没聚焦的档案**只记文字、不播声音**
- 切档案时正在播的声音**立刻停**

界面上的取舍：

- 滑动带里**只放开着的档案**。关掉的档案不轮询、也切不过去，
  放进滑动带就是几页怎么点都没反应的死页 —— 那些在设置页里管
- 往两边到头时箭头淡出（淡出后**不再接收点击**，否则会点到看不见的东西）
- 往上翻历史时**不自动滚到底**：判定依据是消息的 `seq`（盘上发的号），
  不是条数 —— 往上翻会让条数变大，用条数判会被当成"来了新消息"把人拽回去

### 审查过一轮（三段并行：存储 / 运行模型 / 界面）

修掉的：

1. **鉴权失败之后轮询再也起不来**：401 让 `_pollLoop` break，但 `_running`
   还留着 true，而 `startPolling` 拿它当幂等闸 —— 用户改对 token 保存，
   `_syncPolling` 见它"还在跑"直接跳过，那个档案就永远哑着，界面还写着
   "正在听你说"。现在循环退出时把 `_running` 一起复位
2. **结束对话可能要等最多 15 秒**：`stopPolling` 会 `await` 那条循环，而它
   正睡在退避的 `Future.delayed` 里，`abort()` 打不断。现在退避可以被叫醒
3. **关掉/删掉正在说话的档案，声音会接着播完**，而且没听完的那几句会记到
   **新**档案头上（`updateConfig` 改焦点这条路以前什么都不做，只有滑动切换
   会结账）。现在两条路收口到同一个 `_settleBeforeLeavingFocus()`，
   结账对象在进函数时就钉死
4. **删光档案之后补回来的空档案会"继承"被删掉的历史**：它复用了迁移用的
   固定 id `default`，盘上 `history/default/` 还在 —— 看着像删不掉，还顺手
   把 brain 配置清空了。现在补回来的是新 id
5. **配置里一个字段类型不对，全部档案一起归零**：`Profile.fromJson` 用 `as`
   硬转，抛出去被 `ConfigStore.load` 兜成默认配置（还会被下次保存写回盘上）。
   现在类型不对当那个字段没填
6. **半行只能修一次**：写之前就打上"尾巴检查过了"的标记，于是同一次会话里
   一次写到一半失败留下的半行，下一条会接上去一起烂掉。现在每次追加前都
   看一眼最后一个字节
7. **冷启动要把整年历史解析一遍**：`_refreshHasMore` 拿 `loadOlder(limit: 1)`
   去问"还有没有更早的"，而那要从最新一片往回全量扫。现在按 seq 判断（seq 从
   1 连续生成，"最早那条不是 1"就等于前面还有）
8. **设置页不订阅 controller**：改完名字按保存，chip 上还是旧名字；把正在
   编辑的档案删掉之后编辑器绑在幽灵配置上，按保存弹"已保存"其实什么都没写。
   现在整页跟着 controller 重建、选中项记 id 不记下标、`commit()` 返回有没有
   真的写进去
9. **档案全关再开回来，主按钮会画成"旁边那个圆"**（点不动、暗的）：
   `_index` 落在列表外面时没纠正
10. **chip 上头像文件丢了只剩一个空圆**（既没图也没首字）：`CircleAvatar`
    的首字以前只在"没图"时才挂，现在一直挂着，图在时被盖住
11. 旁边那半个圆的无障碍标签说成"开始对话"，实际动作是切档案；设置页那排
    chip 不会滚到当前选中的那个（加了六七个档案就看不见在编辑谁）
12. **切档案之后，排队里还没上传的那几句会发给新档案** —— 用户定的规矩是
    直接丢掉（"切走 = 之前没发出去的不再发了"）。已经在发的那一句拦不住，
    它的目标在开始发的时候就定了，那时候聚焦的还是旧档案，那是对的。
    本地的用户消息是 `/human-to-brain` 成功之后才记的，所以丢掉也不会在
    历史里留半条

**没修、已知的**（都不影响正常使用，写在这里免得当成新 bug 查）：

- 切换的那几毫秒里，旧档案正好回来一条带音频的回复，它可能被排进播放队列，
  由新聚焦的档案播出来（`_playbackEpoch` 只在打断那一刻作废在途音频，
  播放队列本身没有档案属主）。用户说这个几毫秒窗口无所谓，不修。
  上传队列那条的根因和它一样，但已经按"切走就丢"处理掉了
- `loadOlder` 往上翻一页没有索引，代价随翻的深度增长（见 `brain-api.md` §7.2）
