# 说话人识别（声纹）

只让本人的声音进入上行。Silero VAD 负责切句，ECAPA 声纹负责判断
"这一段是不是本人"。注册入口是 `tools/voiceprint` 网页。

## 判定链路

1. Silero 判出语音段，并保留逐帧语音概率。
2. 去掉段两端的外扩，只挑概率高于阈值的帧拼起来，最多 3 秒。
   - 段中间的停顿是纯静音，混进 embedding 会把声纹拉偏，说得越长
     越容易认错。
   - 3 秒是硬上限，所以二十秒的话和五秒的话推理量一样。
3. 送进 ECAPA，和注册声纹算 cosine。
4. 够长的段（≥ 0.3 秒）以 cosine 为准，低于阈值整段丢掉：不上传、
   不进消息流。不足 0.3 秒的段不做比对；当前没有 pVAD 可用，直接放行。
5. 推理失败只摘掉比对器，不影响断句和上传。

阈值默认 0.4。实测本人 0.5~0.7，家人 0.1~0.2，两边分得很开。

## 为什么不用 pVAD 判身份

pVAD 的 sigmoid 主要反映"像不像语音"。实测里目标人和家人说话都能到
0.9；把参考声纹换成零向量、随机向量或另一个人的，输出几乎不动。
它能回答"这段像不像人在说话"，回答不了"是谁"。所以判定换成了
ECAPA embedding 的余弦。`pvad.onnx` 已不再随仓库分发。

## 声纹与模型

- 声纹：192 维，L2 归一化，768 字节的 `spkemb.f32`。
- checkpoint：SpeechBrain `spkrec-ecapa-voxceleb`。注册页和手机必须
  用同一个 checkpoint，换模型之后旧声纹就不能再比了。
- 注册页用 fp32 模型（约 81 MiB，跑在本机，音频不外传）。
- App 内置 int8 模型（约 23 MiB），是同一份权重的静态量化版。

### 量化

动态量化试过：22MB，但保真度只有 0.85~0.98，而且更慢（Mac 上 3 秒
98ms，fp32 是 27ms），放弃。最终用静态 QDQ + per-channel +
reduce_range：

| | 体积 | 0.3 s | 3 s | embedding cosine |
|---|---:|---:|---:|---:|
| fp32 | 84.8 MB | 10.2 ms | 37.3 ms | — |
| int8 | 23.1 MB | 2.9 ms | 17.6 ms | min 0.986 / mean 0.992 |

用 fp32 声纹注册、int8 探针比对，同人 cosine 平均只挪 -0.006，所以
旧声纹不用重录。

两个必须处理的坑：

1. 图末尾按 batch 分支的 `If` 会让静态量化产出无法加载的模型
   （`Argument type mismatch when adding edge`）。导出时换成
   `Squeeze(axis=1)`，App 永远是 batch=1。
2. Fbank/STFT 前端不能量化，否则部分输入会出 NaN。

校准集用 16 kHz 单声道语音：0.3/0.6/1.5/3 秒 × 4 个增益，外加静音和
低噪。脚本在 `tools/voiceprint/quantize_ecapa_int8.py`。

## 性能

ECAPA 每句话只跑一次。会话原来写死 1 路线程，手机上 3 秒音频一次
feed 要 120~143ms；放开到 4 路之后：

- 37.7 秒的段（声纹仍只取 3 秒）：feed 66ms，首次推理含内存池初始化；
- 2.8 秒的段：30ms；
- 稳定值 30ms 左右。

`feed` 耗时包含 Silero 和声纹两部分，但主要开销在后者。

## 已知限制

- 判定是**前缀式**的：最多只看这一段开头的 3 秒。你先说、家人紧接着
  在同一个 VAD 段里继续说，这一整段会按你的声纹放行。要让 VAD 切开，
  中间停顿得超过 `vadMinSilenceMs`（默认 700ms）。
- 只做整段判定，不分离重叠语音，也不在段内检测换人。

## 验证

- Rust：41 个测试通过。
- Flutter：178 个测试通过。
- 真机：本人长句 0.50~0.70 放行；家人连续四段
  0.10 / -0.02 / 0.03 / -0.02 全部丢弃。
