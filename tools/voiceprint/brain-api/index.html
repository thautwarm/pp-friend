Brain API

手机只采音和放音；识别、对话、合成都由 brain（你自己的服务端）承担。这一页是协议本身，照着就能写一个自己的 brain。

与仓库里的 docs/brain-api.md 同源，以它为准。

概览

协议里一共四个端点，客户端只用前两个。后两个是给 agent 的纯文本通道，和客户端这套音频进、音频出不是一回事。

端点 请求 响应 客户端
POST /human-to-brain {brain_id, audio} {kind:"text", text} 使用
POST /brain-to-human {brain_id, skip_before?} 前导 + 连续流：[u32 文本长度][文本][flags]，后面是 Ogg Opus 音频 使用
POST /agent-to-brain {brain_id, text} {kind:"empty"} 未使用
POST /brain-to-agent {brain_id} {kind:"empty"} | {kind:"text", text} 未使用

kind 是载荷判别符：empty 是没有内容，text 是有文本。它不代表操作成败，那是 HTTP 状态码的事。

客户端跑两条互相独立的循环：一条在 /brain-to-human 上长轮询并读取前导和连续音频流，直到这条回复说完；另一条把断句切出来的语音按顺序串行发到 /human-to-brain。

鉴权

两个端点都支持 Bearer token：

Authorization: Bearer <token>
  • token 是用户配置项，和 brain_id 一样，不是生成的。
  • token 可以为空，表示这个部署没开鉴权。空的时候客户端不发 Authorization 头，而不是发一个空的 Bearer。
  • 401 是配置错误，不要当网络问题无限重试。提示 token 无效，停掉轮询。

载荷编码

请求是单个裸的 MessagePack map；/brain-to-human 的响应是二进制前导加一条连续 Ogg Opus 流。不是 JSON，也不是 multipart。音频是原始字节：不是 base64，不是字符串，二进制原样进出。

  • Content-Type / Accept 用 application/msgpack。规范没写明这个取值，客户端把它收在一个常量里，改一处即可。

POST /human-to-brain

把一段人类语音交给 brain，只等转写。断句切出一句话就发一次。请求是一个 MessagePack map：

键 类型 说明
brain_id str 会话句柄，人起的名字，比如 "员工3"。两个端点里必须一致。
audio bin 整句语音，Ogg Opus 16 kHz。没有 WAV 回落。
unheard_text str 可选。上一段回复没被听到的那部分文字，见「打断记账」。

响应：

{ "kind": "text", "text": "..." }

POST /brain-to-human

长轮询 + 前导 + 连续音频流：请求挂住，直到 brain 有话说，先交整条文本，再一边合成一边把音频吐出来。请求是 {brain_id, skip_before?}。响应体是 application/octet-stream：

[u32 大端文本长度][UTF-8 文本][1 字节 flags][Ogg Opus 流…]

// 文本长度 = 0：这一轮没内容，flags 照发
// flags bit0 = 1：skip_before 跳过的旧消息，只有文本、没有音频

前导之后是一条连续的 Ogg Opus 流，不是一帧一个文件：

// 前导（文本一次到齐）
00 00 00 0C  E4 BD A0 E5 A5 BD ...  00

// 紧接着是 OggS 开头的连续流，增量解码即可
4F 67 67 53 ...
  • 文本长度为 0 只是「暂时没话说」，客户端立刻再发一次，不停不等。
  • skip_before 是 UTC epoch 毫秒。早于它的旧消息一条占一条响应（flags bit0 = 1）；客户端一直重发（仍带同一个值），直到拿到真回复。
  • 超时只约束等前导；前导到手后，连接可以一直挂到 body 正常结束。没内容时服务端挂到长轮询上限再回长度 0。
  • body 正常结束 = 说完了，没有结束标记；前导中间断开 = 截断，客户端重发。出声前合成失败回 502。
  • 前导是 [4 字节 u32 大端文本长度][UTF-8 文本][1 字节 flags]，长度只算文本。前导可能跨多个网络分块。
  • 文本长度超过客户端上限是协议错误；body 在前导中间结束是截断，客户端立刻重发。前导之后的字节全部属于 Ogg 流。
  • 不要把整个响应当 UTF-8 解，前导之后是二进制音频。按固定格式切出前导，剩下的原样喂解码器。

音频格式

方向 格式 采样率
上行 /human-to-brain Ogg Opus（audio/ogg） 16 kHz
下行 /brain-to-human Ogg Opus（audio/ogg） 24 kHz
  • 两个方向采样率不同，是跟着模型走的：识别吃 16 kHz，合成出 24 kHz。
  • 下行是一条连续的 Ogg 流：增量解析 page、重组 packet、逐包解码，把 PCM 追加到播放队列。不能按 HTTP 分块当独立文件，也不能等整个 body。
  • 实现时注意：Opus 内部固定跑 48 kHz，解码出来的采样率未必等于声明的采样率。要读解码器的实际输出再重采样，写死会变速。

打断记账：unheard_text

brain 说到一半被打断，客户端要告诉它「哪一段没进到用户耳朵里」。报的是文字不是时间点：光给一个毫秒数，brain 还得自己把文本和音频对齐。

协议给的是整条文本和一条连续音频流，客户端不知道每个采样对应哪个字，只能按「播放头走过的采样数 / 已经推进队列的采样数」估算听到了正文的哪个位置。

估出来的位置再对齐到句子边界：流已经结束时往后取整句；流还没结束时往前收到句首，整句算没听到。估错最多影响一句，并且偏向「少算听到」。

被打断之后，下一句 /human-to-brain 多带一个可选字段：

  • unheard_text：没听到的那部分文字，包括正在播的那一条没听完的尾巴，加上后面已经入站但还没播的整条回复。
  • 客户端还会附带一个 heard_ms（听到的毫秒数），纯粹供诊断。它不在规格里，服务端应当忽略未知字段。
  • 只在真的被打断过才出现。没打断就不带这个键：「没带」和「空字符串」是两件事。
  • 账是累加的，挂在下一句用户的话上一起走，上传成功才清，失败留着。

错误与重试

协议层没有错误响应，失败只来自网络和 HTTP 状态码：

情况 处理
网络错误 / 5xx 客户端退避重试：500 ms 起，翻倍，15 s 封顶。
等前导超时 不是错误：当作这一轮没内容，立刻重发。
body 在前导中间结束（截断） 立刻重发，不走退避；连续 3 次才让 200 ms。
音频流中途连接中断 已播放的照播，不重投：服务端不会重发这条。这条按「没说完」记账，下次打断时把没听到的尾巴带进 unheard_text。
401 / 403 不重试。提示 token 无效，停止轮询。
文本长度非法 协议错误，重试大概率还是错。

最小示例

字段名就这些。一个能跑的 brain 只需要接两种请求，并会写「前导 + 连续 Ogg 流」。仓库里有一个按这个协议手写的假 brain（tools/mock_brain.py，含一份独立的 MessagePack 实现、前导、连续 Ogg 流和 skip_before 支持），可以拿来对照。

POST /human-to-brain
Content-Type: application/msgpack
Authorization: Bearer <token>   (optional)

{ "brain_id": "员工3", "audio": <bin> }

# interrupted last time:
{ "brain_id": "员工3", "audio": <bin>, "unheard_text": "..." }

# response:
{ "kind": "text", "text": "..." }
POST /brain-to-human
Content-Type: application/msgpack

{ "brain_id": "员工3", "skip_before": 1728000000000 }

# response: application/octet-stream
# [u32 BE text length][UTF-8 text][1 byte flags][Ogg Opus stream...]

# nothing to say: length = 0, flags = 0, no audio
00 00 00 00 00

# normal reply
[length]["..."] 00 [OggS ...]

# skipped old message: flags bit0 = 1, no audio
[length]["..."] 01
