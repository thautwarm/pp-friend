# PP Friend

[English](README.md) · [中文](README.zh.md) · [日本語](README.ja.md)

A self-hosted real-time voice assistant client. The phone does two things — **capture audio and play audio**; recognition, conversation, and speech synthesis all run on your own server (called the **brain** in the code).

**PP is Push and Pull.** Both sides push and both sides pull. The phone pushes your speech to the brain and long-polls for its reply; the agent pushes its text in and pulls human text out. All four channels stay open at once, so the collaboration is asynchronous: the agent can speak while you are still talking.

> **Made with deepseek v4.1 flash and pp-friend itself.**
> The project was built with PP Friend: requirements, reviews, and fixes were dictated to the coding agent by voice, through the phone.

---

## What it is

A voice assistant you can talk to at any time, running on a brain in your own home, with your data staying on your own server.

- **Full duplex**: you speak while the AI listens, and the AI speaks while you listen — both directions open at once
- **Barge-in**: if you start talking while the AI is speaking, it stops immediately; it reports "where I was cut off" to the brain instead of letting the brain think it finished
- **Keeps running in the background**: switch apps or lock the screen and the conversation continues (a foreground service holds the recording); if the other app takes audio focus (video, music), voice pauses without dropping the connection and resumes when you come back
- **Local endpointing**: Silero VAD runs on the phone (Rust); only complete utterances are uploaded, not a continuous audio stream
- **Speaker verification**: compares your voiceprint against each utterance with ECAPA cosine similarity; long enough utterances below the threshold are dropped entirely — family members' speech is neither uploaded nor added to the agent's context
- **Multiple profiles**: each profile has its own brain configuration and history and can run concurrently; only the focused one plays audio, the others only record text

Record a short sample in the browser, download `spkemb.f32`, then import it in the app under **Settings → General → Speaker verification**. Recording and inference happen locally in the browser; audio is never uploaded. The site source lives in `tools/voiceprint`; the app also has a "Create your voiceprint locally and download it" button.

## Architecture

**The phone does not hold conversation context** — that belongs to the server. Switching the brain name switches to another conversation. What the phone stores locally is only **display history**: it is not part of any request, and deleting it does not affect the conversation.

| Layer | Technology |
|---|---|
| UI / business logic | Flutter (Dart 3.13) |
| Local endpointing | Rust + Silero VAD, flutter_rust_bridge 2.13 |
| Speaker gating | Rust + ECAPA cosine similarity (int8 ONNX, 23 MB); voiceprints are generated by the `tools/voiceprint` web page |
| Audio engine | Android native (Kotlin): AudioRecord / AudioTrack / AEC |
| Uplink encoding | Ogg Opus 16 kHz (MediaCodec + MediaMuxer) |
| Downlink decoding | Continuous Ogg Opus 24 kHz (incremental parser + MediaCodec) → resampled to 16 kHz |
| Communication with the server | HTTP + MessagePack; request/response uplink, prelude (text) + continuous audio stream downlink |
| History on disk | NDJSON, split into 1 MB chunks, append-only |

**Android arm64 only**, minSdk 29. The Dart side of the iOS contract exists; the native side does not.

## Build

Prerequisites: Flutter 3.47+, Android NDK, Rust toolchain.

```bash
# 1. ONNX Runtime (the Android .so is checked in; only needed for host cargo test)
tools/fetch_onnxruntime.sh

# 2. Build — a fresh clone builds without NDK; the .so in jniLibs is checked in
flutter build apk --release

# 3. Only rerun this after changing Rust source (commit the artifacts with it)
tools/build_rust_android.sh
```

## Releases

GitHub Actions (`.github/workflows/build-release.yml`) runs `flutter analyze`
and `flutter test`, then builds the arm64-v8a release APK on every push to
`main`, every pull request, and manual dispatches. The APK is attached to the
workflow run as an artifact.

To publish a GitHub Release, push a tag (keep it in sync with the version in
`pubspec.yaml`):

```bash
git tag v1.0.0
git push origin v1.0.0
```

A manual dispatch can also create a release by filling in its `release_tag`
input.

## End-to-end self-test

The repository ships a **hand-written fake brain** that follows the protocol, so the whole path can be exercised without any server:

```bash
tools/mock_brain.py
```

It includes its own MessagePack implementation, which helps check whether our reading of the protocol has drifted. `/brain-to-human` is emitted as `[u32 big-endian text length][UTF-8 text][1-byte flags]` followed by a continuous Ogg Opus stream, with `skip_before`, `--no-audio`, `--truncate` and `--failed` support.

```
assets/         model assets (ecapa.onnx, int8)

```
